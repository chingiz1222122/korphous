# План Телеграм-бота для мониторинга чатов и ответов на вопросы

## Что реально умеют боты и что нужно для чтения чатов
- **Bot API** не позволяет читать историю и сообщения во всех чатах по умолчанию. Бот видит только те чаты, куда его добавили, и только новые сообщения с момента добавления. Поэтому классический бот не сможет «прочитать всё», если его не пригласили и не дали доступ. 
- Для полноценного мониторинга выбранных чатов (включая чтение истории, поиск и получение сообщений) обычно используют **MTProto-клиент под обычным аккаунтом** (например, Telethon или Pyrogram). Такой клиент действует как «юзербот» и может читать чаты, к которым у аккаунта есть доступ.

**Практический вывод:** если вам нужно отслеживать «нужные чаты» и делать отчёты за период, надежнее строить решение на MTProto-клиенте (юзер-аккаунт) + отдельный бот-«интерфейс» для диалога.

## Архитектура решения
1. **Сбор данных (ingestion)**
   - MTProto-клиент подписывается на выбранные чаты/каналы и сохраняет сообщения в базу данных (например, Postgres или SQLite).
   - Сохраняются: `chat_id`, `msg_id`, `date`, `text`, `from_id`, `entities`, `media`, `reply_to`, и т.д.

2. **Хранилище и индексация**
   - Индексация по периоду, чату, ключевым словам.
   - Опционально: векторизация текста (embeddings) для семантического поиска.

3. **Слой анализа / LLM**
   - Суммаризация «важных» сообщений за период.
   - Ответы на вопросы в стиле ChatGPT («какие мероприятия анонсированы»).
   - LLM работает по результатам поиска/фильтрации сообщений, чтобы не выдумывать.

4. **Интерфейс общения**
   - Бот в Telegram принимает вопросы пользователя.
   - Отправляет ответ + **список ссылок** на конкретные сообщения.

## Как получать корректные ссылки на сообщения
- **Публичные каналы/чаты**: `https://t.me/<username>/<msg_id>`.
- **Приватные супергруппы**: `https://t.me/c/<internal_id>/<msg_id>`.
  - `internal_id` — это `chat_id` без префикса `-100` (например, `-1001234567890` → `1234567890`).

Важно хранить `chat_id` и `msg_id`, чтобы всегда уметь построить ссылку.

## Пример запроса пользователя и логика ответа
**Запрос:** «какие мероприятия анонсированы в этом чате за неделю?»
1. Определить чат (по контексту или запросить уточнение).
2. Выбрать сообщения за период.
3. Отфильтровать по ключевым словам («ивент», «митап», «воркшоп», «регистрация», даты).
4. Сформировать ответ:
   - Короткое резюме.
   - Список пунктов: *название + дата + ссылка на сообщение*.

## Рекомендованный стек (Python)
- **MTProto-клиент:** Telethon или Pyrogram.
- **Хранилище:** SQLite (MVP) → Postgres (prod).
- **LLM:** OpenAI API или локальная модель, с RAG-подходом.
- **Telegram Bot API:** aiogram/pyTelegramBotAPI для интерфейса.

## Риски и ограничения
- Юзербот — это пользовательский аккаунт, важно соблюдать правила Telegram.
- Нужны безопасное хранение сессий и токенов.
- Некоторые чаты запрещают ботов/юзерботов.

## Предлагаемый MVP-план
1. Авторизация MTProto-клиента, выбор 1–2 чатов.
2. Сбор и сохранение сообщений в БД.
3. Простая выдача по ключевым словам + ссылки.
4. Добавить LLM-суммаризацию и ответы на вопросы.
5. Расширить на больше чатов и периодов.

## Конфигурация под ваш сценарий
- **Тип чатов:** публичные чаты и каналы, где вы уже состоите.
- **Период:** 24 часа (суточная сводка).
- **Фильтры:** настраиваемые темы/ключевые слова (например: мероприятия, вакансии, релизы).

Рекомендуемая стартовая реализация:
1. Задать список чатов для мониторинга (ID/username).
2. Каждый час или раз в сутки собирать новые сообщения.
3. Перед выдачей применять фильтры и формировать сводку.
4. Отвечать списком пунктов + ссылками на сообщения.
